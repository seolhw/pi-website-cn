## 为什么选 Pi？

Pi 是一个极简的 agent harness。用[扩展](/docs/extensions/)、[skills](/docs/skills/)、[提示模板](/docs/prompt-templates/)和[主题](/docs/themes/)定制 Pi，并打包成 [Pi 包](/docs/packages/)通过 npm 或 git 分享。

Pi 自带强大的默认能力，但刻意不内置 sub-agents、plan mode 这类功能。想要什么，直接让 Pi 自己构建，或者安装一个符合你工作方式的包。

四种运行模式：交互式、print/JSON、[RPC 与 SDK](/docs/sdk/)。真实集成案例：[OpenClaw](https://github.com/openclaw/openclaw)。

## 我们刻意没有做

Pi 极度可扩展，因此不需要规定你的工作流。其他工具内置的功能，都可以通过[扩展](/docs/extensions/)、[skills](/docs/skills/)或者第三方 [Pi 包](/docs/packages/)补齐。

<div class="not-built">
	<div>
		<h3>~没有 MCP~ 现在有 MCP + Codemode</h3>
		<p>MCP 已内置，Codemode 让 agent 在 JavaScript 沙箱里组合工具调用，同时也仍然支持 MCP 扩展。</p>
	</div>
	<div>
		<h3>没有 sub-agents</h3>
		<p>用 tmux 启动多个 Pi 实例，或者用扩展自己实现，也可以安装别人做好的包。</p>
	</div>
	<div>
		<h3>没有权限弹窗</h3>
		<p>在容器里运行，或者根据你的安全要求，用扩展实现自己的确认流程。</p>
	</div>
	<div>
		<h3>没有 plan mode</h3>
		<p>把计划写进文件，或者用扩展构建，或者直接安装一个包。</p>
	</div>
	<div>
		<h3>没有内置待办</h3>
		<p>用一个 TODO.md 文件，或者用扩展写一套你喜欢的方案。</p>
	</div>
	<div>
		<h3>没有后台 bash</h3>
		<p>用 tmux。完整可观测，可以直接交互。</p>
	</div>
